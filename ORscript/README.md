# OR — Roblox Studio + AgentScript AI agent

Turn a supported AI chat (**DeepSeek, ChatGPT, Claude, Google Gemini, Kimi, NVIDIA NIM Kimi K3, GLM, Qwen, Arena, Meta AI, Crax GPT, Ox Alpha, Vani Chat, ClickUp Brain, CodeCraft API (bring your own key), or Notion AI (experimental)**) into an autonomous development agent. Two switchable engines:

| Engine | Toggle | Target | Port |
|---|---|---|---|
| **Roblox** (RS) | RS | Roblox Studio via its built-in MCP server | ws://127.0.0.1:17613 |
| **AgentScript** (AS) | AS | A local project folder — files + terminal | ws://127.0.0.1:17615 |

Describe what you want in plain English and the AI builds instances, writes Luau/code files, sculpts terrain, tunes lighting, generates UI, runs builds and tests, and audits your project — inside Studio or directly on disk.

Website adapters require no API keys. Optional direct API providers use the provider's own billing and credentials. Chromium browsers (Chrome, Brave, Edge, Thorium). Theme is black/white outlines.

---

## Engines

- The bar above every supported chat composer carries a segmented **RS / AS** toggle. Switching engines wipes tool caches so commands cannot cross engines.
- **RS** drives Roblox Studio through StudioMCP (stdio JSON-RPC spawned by `or-agent`), including the `animation_*` workflow.
- **AS** gives the AI full control of one local folder ("the workspace") through native Rust tools — sandboxed paths, exact-match diff editing, glob/content search, and terminal execution with hard timeouts.

Large `execute_luau` scripts are auto-chunked around 24 KB so Studio's parser never hits the ~64 KB wall. Each chunk is still one NDJSON/JSON-RPC line.

## Setup

1. Open `chrome://extensions` → Developer mode → **Load unpacked** → this folder (`manifest.json`).
2. Start the bridge — **ORscript Desktop**, the Rust app in `agent/` (Windows: build once with `Build-ORscript-Desktop.cmd`; macOS: `./build-orscript-desktop.sh`; or `cd agent && cargo build --release`). Launch `bin/or-core.exe` (Windows) / `bin/or-core` (macOS):
   - Workspace window: Home / Explorer / Tools / Servers / Terminal / Settings — live Bridge / Roblox Studio / Tools / Workspace status, Studio viewport snapshots, a Luau runner that executes inside Studio, and a workspace folder you can switch without restarting.
   - Closing the window hides it to the notification area; the bridge keeps running. Background controls: **left-click the ORscript tray icon** (or launch `or-core` again) to reopen the window, right-click → **Quit** (or the **Quit** pill in the title bar / Settings) to stop the bridge and exit. If no tray icon could be created, Close quits instead of hiding so the app can never become unreachable. `--hidden` starts in the tray, `--headless` runs without any window.
   - It starts the HTTP API on `http://127.0.0.1:3000`, the WS bridges on `17613` (RS) and `17615` (AS), and the AgentScript workspace (`OR_WORKSPACE_ROOT` / `--workspace` / Settings → Workspace / `%USERPROFILE%\ORWorkspace`).
   - Runs on Windows and macOS — the platforms Roblox Studio ships for. See `agent/README.md` for build details, per-OS paths and flags.
3. **RS:** Roblox Studio → Assistant AI → ⋯ → Manage MCP Servers → Enable Studio as MCP Server.
4. Open a supported chat and click **Start agent**.

### Provider notes

- **ClickUp Brain (1.28.0)** — [app.clickup.com](https://app.clickup.com/) hosts ClickUp's AI *inside* the workspace app (side panel / modal from the **AI** or **Ask AI** button, or the Brain page under `/<workspace>/ai`). The same page is full of other rich-text editors (tasks, Docs, comments, Chat channels), so `src/providers/clickup.js` scores every visible editor — Brain markers (`cu-ai-*`, `ai-chat` / `brain` classes, an "Ask AI…" placeholder) score up, task/comment/doc/channel markers score down — and refuses to attach when nothing scores as Brain (the bar then says *open Brain first*). Transcript rows are read only inside the Brain surface (largest AI-marked ancestor of the composer), by role markers first and by shape second; workspace mutations outside it are ignored. Typing goes through `insertText` → synthetic plain-text paste → DOM fallback so Quill / ProseMirror state stays in sync and markdown shortcuts do not mangle JSON. Brain gets the compact system prompt + command index (`sysMaxChars` 14000, `commandListMaxChars` 12000), the catalogue is force-injected if it answers the bootstrap in prose, and its prompt extra forbids ClickUp actions (no tasks/docs/comments from our messages). Allowance / upgrade prompts surface as a bar warning. Written without a live ClickUp DOM: if Brain's markup differs, `[rs-diag] clickup.*` lines show what was found.
- **CodeCraft API (1.26.0)** — [codecraftapi.com](https://codecraftapi.com) is an OpenAI-compatible API (33 models — Claude, GPT, Gemini, DeepSeek, Kimi, Qwen, GLM, Grok, Seed… on one key) with **no web chat page**, so ORscript ships its own: popup → **CodeCraft API chat (own key)** (or the AI switcher in the bar) opens `codecraft.html`, an extension page running the exact same bundle as a hosted site. Paste a `cc_` key once (Dashboard → API Keys), pick a model from the live `/v1/models` list, press **Start**. Replies stream over SSE into the transcript (reasoning in a collapsible block, images as vision parts, `###LUA###`/JSON commands masked behind the usual chips); the key lives in `chrome.storage.local` and is sent to `codecraftapi.com` only. HTTP 401/402/429 are shown on the reply and in the bar (`modeWarning`), each conversation keeps its own `#c=…` id (**New chat** resets it), and the compact command index is used by default because every token is billed to the user's plan. **1.36.0** turned the page into a full chat app: a persistent **chat library** sidebar (every conversation saved in `chrome.storage.local` — search, pin, rename, delete, switch; reopening an agent session restores the ORscript state), **message actions** (copy, edit & resend, regenerate, delete, copy-code bars on every block), a **generation settings** drawer (temperature, max tokens, reasoning effort, custom instructions as a system message, Ctrl+Enter mode), **auto-retry** on 429/5xx, a **usage meter** (per chat + profile-wide, from the API's `usage`), reply stats (time, first token, tokens, tok/s), **export** (Markdown / JSON) and **import**, drag-and-drop images, quick prompts, a jump-to-latest pill and keyboard shortcuts. Tests: `node tests/test-codecraft.js`, `node tests/test-codecraft-pro.js`, `node tests/codecraft-e2e.js` (jsdom; `NOKEY=1`, `ERR402=1`).
- **Crax GPT** (`gpt.crax.lol`) — the site sends its own `role: system` prompt ahead of every request ("you have no tools"), which made every Crax model ignore the ORscript protocol even though the bar showed *RS Connected*. ORscript now runs a MAIN-world tap (`src/providers/crax-net.js`) that prepends the agent instructions to Crax's chat request while a session is starting or running, so all Crax models link to Studio again. Nothing is sent while the agent is off.
- **Notion AI** (`notion.so/chat`, `/ai`) — **experimental**, ported from the PlazCode Notion adapter. Notion's transcript is immutable, so command status is shown as ORscript cards next to each AI message instead of in-place chips; the bar sits on a provider-reserved strip above the composer; the Start message is phrased as plain-text *user preferences* (no Markdown blocks) so Notion's reviewer does not drop it; long tool results (the command catalogue, big script reads) are attached as `orscript_*.txt` files. Notion's own Agent is not reconfigured — ORscript only reads and writes the chat. The bar never hides on Notion: before the AI composer mounts (or on a normal Notion page) it docks to the bottom of the viewport and its status line says what it is waiting for — use the full-page chat at `notion.so/chat` or `notion.so/ai`. Hooks that exist only in the PlazCode core (native-generation respect, fresh-response gating, activity summaries) are ignored by the ORscript core.
- **ChatGPT (1.21.1)** — adapter re-synced with the current chatgpt.com DOM: the composer is found whether it is the classic `#prompt-textarea` ProseMirror box, the newer Lexical/`data-testid="composer-input"` editor or a plain `<textarea>` (Work mode), the single submit control is read through `#composer-submit-button` plus send/stop test-ids inside the composer frame, bulk `insertText` is used for the bootstrap (line-by-line only for huge results) and the composer is kept visually blank while internal messages are typed. Turn detection understands `article[data-turn]`, `data-turn-key` grouped turns and Work result units. Fixes "Start clicked but nothing is typed/sent".
- **Notion AI (1.21.1)** — composer detection no longer stalls at "waiting for the chat composer": the placeholder vocabulary was widened (Ask Notion / Ask the agent / Ask, search… / What do you want to…) and, on a confirmed `/chat` or `/ai` route, a relaxed fallback picks the chat-shaped editable nearest the bottom of the viewport after 2.5 s of strict misses (page editors never live on those routes, so this cannot touch a document). The pre-start bar line now reports how many visible text boxes the page has, which is the first thing to paste when reporting a Notion issue.
- **Provider scan (1.20.0)** — `node tests/test-provider-wiring.js` cross-checks every AI chat host against the manifest bundles, the background `PROVIDER_URLS` allow-list, the in-bar site switcher and the provider skins. It found and fixed three gaps: `agent.minimax.io`, `overchat.ai` and `huggingface.co/chat` were injected but missing from the background allow-list (the service worker refused to open/route them), Ox Alpha had no entry in the site switcher, and the switcher pointed Notion at `/ai` while the extension prefers `/chat`. Still open by design: `host_permissions` is `<all_urls>` — far broader than the 42 chat hosts actually used; narrowing it is a store-listing decision, not a code fix.

## Paint — draw it, the AI builds it

The brush button next to Settings (or **Ctrl/⌘+Shift+P**) opens **ORscript Paint**, a full-screen studio on top of the chat page (`src/core/paint.js`).

- **Tools (16):** pencil, brush (soft, pressure-aware), marker (multiply), spray, eraser, bucket fill (tolerance), colour picker, line, arrow, rectangle, ellipse, triangle, star, text, rectangle select (move/cut/copy/paste/flip), hand. Shift constrains shapes and lines; right-button paints with the secondary colour.
- **Params:** size 1–200px, opacity, hardness, flow, spray density, fill tolerance, line dash, shape mode (outline / filled / both), corner radius, star points, arrow heads, font size/bold; 24-colour palette + custom + recent colours; canvas presets (16:9, 4:3, square, portrait, 2K) or any size up to 4096², background (white/black/grey/transparent/blueprint), grid with optional snapping, mirror symmetry (X/Y/both); up to 8 layers with opacity, visibility, reorder, duplicate, merge, flip; 60-step undo/redo; zoom 10–1600% and pan (space/middle-drag).
- **Import:** paste or drop an image, open a file, or capture the Studio viewport straight onto a layer to annotate it.
- **Send to AI:** pick an intent (auto, 3D structure, top-down level, UI mockup, terrain, character, systems diagram, animation, annotate screenshot), add an optional note and scale hint, and press *Send to AI*. The painting is sent as the next user turn — ORscript starts the agent first if it is not running, waits out a busy step, attaches the PNG on sites that accept images, and always includes a **vector trace**: every element in drawing order with colour, shape, position/size in canvas %, text labels, inferred relations (arrows between elements, containment), and an ASCII occupancy map — so even image-less providers get the exact drawing. Intent-specific *HOW TO ACT* rules tell the agent to name what it sees, build it with the engine's commands, and screenshot-verify (Self-check) the result; *Plan first* asks for a short build plan before any command.
- `node tests/test-paint.js` guards the bundle wiring, the bar button/hooks, the CSS and the message builder.

## Agent

- Native crate: `agent/` (`or-agent` 1.38.0) — the or-core bridge plus the ORscript Desktop window (eframe/egui) with, since 1.37.0, an **AI Chat side panel**: bring your own API key (CodeCraft, OpenAI, OpenRouter, Groq, DeepSeek, Gemini, xAI, Mistral, Together, local Ollama / LM Studio, custom URL), pick a model from `/models`, and the model drives Studio through the bridge's own tools (Studio MCP, plugin commands, workspace files) — see `agent/README.md`.
- Service worker skips stale-socket reconnect and MCP heal while a `call_tool` is in flight (the 25 s stale window used to kill long tools).
- 637 advertised Studio commands (27 of them the 1.22.0 work-mode pack, 13 the 1.29.0 design pack, 11 the 1.30.0 gfx pack, 6 the 1.31.0 blueprint pack, 6 the 1.32.0 project pack, 2 the 1.33.0 inspect pack) plus 110 hidden legacy aliases that stay callable (`list_commands`), a 24-command animation suite, AgentScript file/terminal tools.
**1.38.0 — Modes & commands overhaul: a catalogue grouped by family, playbooks per mode, and a mode evidence gate.** "Improve the modes / do something about the commands" — both halves of the AI's working memory were reworked.
- **Commands — the catalogue the model reads is now organised.** The signature tier is grouped into **18 command families** (`SCRIPTING`, `SYSTEM BLUEPRINTS`, `DATA, REMOTES, NETWORK & MONETIZATION`, `GAMEPLAY SYSTEMS`, `MODELING & BUILD`, `PHYSICS, RAYCASTS & MECHANISMS`, `TERRAIN`, `LIGHTING & ATMOSPHERE`, `VFX & PARTICLES`, `UI & HUD`, `THUMBNAIL & ICON STUDIO`, `AUDIO`, `ANIMATION`, `TWEENS, SPRINGS & CAMERA`, `PLAYTEST & DEBUG`, `STUDIO CONTROL, PLUGIN & OR`, `WEB & API`, `OTHER`) under `SIGNATURES BY FAMILY (callable as shown; <MODE> families first):` with `── FAMILY (n) ──` headers — the **active work mode decides the order**, so Ultimate sees scripting/blueprints/data/build/physics with full signatures, Visualizer sees lighting/VFX/UI/thumbnail/audio, Animator sees animation/tweens-camera/playtest. What does not fit the budget is listed under `NAMES ONLY (call them directly; a wrong parameter returns the exact schema, never look them up):` **grouped by family too**, instead of one 600-name blob. Measured: 697 commands in ~23 KB / 128 lines for the compact budget, ~19 KB / 110 lines embedded.
- **Clutter removed.** The 34 `studio.x {}` MCP alias rows and the raw `screen_capture` are hidden (`or_screenshot` is the advertised path); duplicate helper lines are deduplicated by label; the FOCUS header no longer claims "all listed with signatures" when they are not.
- **Signatures are honest.** `sigFromLine` reads the parameter lines only (it used to pick up description examples — `blueprint_configure` advertised a `Rewards` parameter that does not exist); required parameters come first in every signature; `packSignatures` is strict-prefix so nothing is listed both as a signature and as a name (`blur_set` appeared twice before).
- **Heavy commands get time.** Every skill ran as a 20 s `execute_luau`; `project_index_*`, `project_health_report`, `blueprint_install/verify/remove/configure/status`, `script_analysis`, `diagnostics_*`, `audit_*`, `model_optimize`, `workspace_export` and the symbol tools now pass a 90 s budget (`_orTimeout`, stripped from the wire) — the other half of the `project_index_build` "did not respond" errors.
- **Modes — playbooks.** `WORK_MODE_PLAYBOOKS` (config.js): four command chains per mode, appended to the full profile and to the switch note. Ultimate: NEW SYSTEM / BUG FIX / EXISTING PLACE / BUILD. Visualizer: MOOD PASS / HERO VFX / UI SCREEN / THUMBNAIL & ICON. Animator: COMBAT CLIP / LOCOMOTION LOOP / PROP & UI MOTION / CUTSCENE. Every chain ends in its verification step.
- **Modes — evidence gate.** `MODE_GATES` + `modeGateNudge` (main.js): once per run, when the loop is about to accept the final answer after ≥2 tool turns and the mode's "did" set ran (scripts written / look changed / motion authored) but no proof command did (`script_read`+`script_check`/playtest; `or_screenshot`/`gfx_capture`; `animation_preview`/playtest), the loop submits a `━━━ <MODE> GATE ━━━` system note asking for the verification instead — diagnostics `loop.modeGate`, toast "Work-mode gate — asking the model to verify before it finishes". Runs after the commandless-retry rescue, never instead of it.
- Mode cards: each note now states the catalogue order, the playbooks and the gate.
- Tests: `tests/test-v138.js` (runs the real `buildCatalogue` per mode over the real skill lines: family order, budget, no signature/name duplicates, no alias rows; `sigFromLine`/`toolSignature`/`packSignatures`; playbooks; the gate as a function and its loop wiring; version pins). `tests/test-work-modes.js` bounds raised for the playbooks. **1.37.1 — no command searching; project_index_build / blueprint_list hardened.** Two behaviours the agent kept falling into — browsing the command registry instead of acting, and looping on `project_index_build` / `blueprint_list` errors (Studio offline, big-place timeouts, 34 KB programs) — are closed structurally.
- **The AI never searches commands any more.** `search_commands`, `get_command`, `command_registry_stats` and `generate_command_docs` are no longer advertised; they and `list_commands {query}` are answered by `noSearchReply`: "COMMAND SEARCH IS DISABLED", at most five closest signatures (typo-safe) and an order to act or use `execute_luau`. Every catalogue / reminder / error text that used to say "look it up with list_commands", "fetch its parameters before use", "never guess parameters" now says the opposite: the catalogue is complete, names without a signature are callable, a wrong parameter returns the exact schema in the error. The system prompt carries a hard `NO COMMAND SEARCHING` rule (COMMAND PLATFORM block), `COMMAND_NOT_FOUND` offers the closest names + `execute_luau` instead of "run list_commands again", and `orscript_help commands` documents the policy.
- **FIRST MOVE is conditional.** Openers are picked only when they match the request (complete game system → `blueprint_list`; existing place with scripts to understand → `project_index_build`; simple request → just do it), never blindly, never while Studio is offline; if an opener errors the model states it in one line and continues — no retries, no substitute search (Operating loop, Ultimate mandate, PROJECT INDEX line, full + tight).
- **`blueprint_list` works without Studio.** The catalogue is JS data, so main.js answers it locally (`RobloxScriptSkills.blueprintListLocal`) and only asks Studio with a ~400-byte installed-state probe (`blueprintInstalledProbeLuau`) instead of the 34 KB program; offline/busy Studio degrades to `installed: "unknown"` + a note, never an ERROR.
- **`project_index_build` is bounded.** The Luau caps `added` / `modified` / `removed` at 60 paths each (totals + `lists_truncated` kept — a first build of a 600-script place no longer returns tens of KB); an explicitly disconnected Studio gets one clear "skip the index and continue" refusal (never on a stale/unknown bridge state); a transport timeout retries once with `max_scripts: 150` and labels the result partial; offline feedback for `project_index_*` / `blueprint_*` carries the no-retry / no-search line.
- Tests: `tests/test-v1371.js` (string + functional checks of `noSearchReply`, the local blueprint catalogue and the capped build program); `tests/project-index-sim.py` 89/89, `tests/blueprints-sim.py` 100/100, `tests/luau-runtime-scan.py` clean. **1.35.0 — Reliability, stability and performance pass.**
- **The placement loop no longer does a full layout pass on every animation frame.** `placeBar` ran provider editor/composer lookups, `getBoundingClientRect` reads, reserved-strip padding writes and tray `offsetHeight` reads 60 times a second, forever, on top of the host page's own work. It keeps the rAF heartbeat (so a detached `#rs-root` still self-heals within a frame) but runs the body only every frame for 700 ms after a trigger (resize / scroll / wheel / pointer / key / focus / input / transitions / visibility / visualViewport, a bar content change, a cards re-render), else every 100 ms while a session is live or a tray is open, else every 200 ms. Measured in the jsdom harness over 3 s idle: placement passes 185 → 14, `getBoundingClientRect` 373 → 31, `querySelectorAll` 484 → 26.
- **Fixed: the bar was detached and re-attached on every frame on the CodeCraft page.** `barMount()` returned `before: comp.firstElementChild`, which is the bar itself once mounted, so the core's "out of place?" check was always true and `insertBefore` ran ~60×/s. Besides the churn, that is what kept stealing focus from our own trays (task input, Public composer, search box). The core now re-inserts only when the bar is genuinely out of place (`before === bar` and `before: undefined` are treated as in place) and CodeCraft skips the bar when computing `before`.
- **Cards panel: one rebuild per burst, never under your cursor.** A batch of 6 commands fired `trackCard` twice per command, each one rebuilding the whole panel synchronously (12 rebuilds); skill / task / template / roadmap change events did the same. `scheduleRenderCards` coalesces them into one rebuild per frame and defers (retrying every 400 ms) while an input, textarea, select or contenteditable inside the panel has focus - so an AI task update can no longer eat the task you are typing. The Activity "ago" refresh is time-based (5 s) instead of a frame counter.
- **Per-tab error boundary.** If one tab's renderer throws (a malformed template, a broken skill store) the panel used to go blank with the tabs dead. The broken tab now renders a fallback block with the message and a *Try again* button; the other tabs keep working; `cards.tabFailed` is logged.
- **`bg()` can no longer hang the loop.** Every background call now has a finite ceiling - the background's own tool timeout + 20 s (floor 15 s), or 150 s - so a service worker torn down mid-call or an extension update landing during a tool returns `BACKGROUND_TIMEOUT` instead of leaving the input locked forever. `lastError` mapping to `stale-extension` / `disconnected` is unchanged.
- **Studio plugin poller.** While or-core is down the hello backs off 3 → 15 s instead of knocking every 3 s for hours; consecutive poll failures wait 2 s × failures (max 10 s); the loop body is `pcall`-guarded so one unexpected error cannot kill the poller for the session; and a finished job's result POST is retried up to 4× with backoff (the job itself is never redone) instead of being dropped when the bridge hiccups.
- `window.__rsPerf()` exposes placement-pass and panel-render counters so these numbers can be checked live. Tests: `tests/test-v135.js` (20 string checks + jsdom measurements: idle pass/read budget, hot-on-scroll, no bar re-insertion, 12 trackCards → 1 rebuild, focus guard, error boundary + Try again).

### Theme preview (no extension load needed)


`node tests/test-theme-visuals.js` guards the 1.19.7 visual layer (per-theme tokens, swatch photos for all 16 themes, SVG corner ornaments + inside textures, pill button states) and the sound packs. Decorations are designed SVG motifs (`--orx-orn` in `overlay.css`) painted with the theme gradient — never emoji or text.

### Sound packs

Every theme ships seven hand-tuned Web Audio effects — `start`, `done`, `stop`, `error`, `ok`, `click` and a `special` signature — defined as data in `THEME_SOUNDS` (`src/core/main.js`) and rendered by a single synth (`playSfx(kind, themeId)`): oscillators with glide, lowpass, detune/chorus and vibrato, plus filtered noise. Every effect is under one second and never loops. The ♪ pills under the theme picker preview the current pack; the preview harness above plays the same code.

## Privacy

There is no OrScript telemetry. Local tool bridges use `127.0.0.1`; enabled API integrations contact only their configured HTTPS provider endpoint. AgentScript stays inside the workspace root unless you flip FULL ACCESS.


## Studio MCP reliability

Studio operations use Roblox Studio's supported MCP server through the local OrScript agent. Timed-out MCP calls are not replayed, `script_read` has a bounded 30-second extension timeout, and reconnect retries are limited to disconnected read-only requests.

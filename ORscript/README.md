# OR — Roblox Studio + AgentScript AI agent

Turn a supported AI chat (**DeepSeek, ChatGPT, Claude, Google Gemini, Kimi, NVIDIA NIM Kimi K3, GLM, Qwen, Arena, Meta AI, Crax GPT, Ox Alpha, Vani Chat, ClickUp Brain, CodeCraft API (bring your own key), or Notion AI (experimental)**) into an autonomous development agent. Two switchable engines:

| Engine | Toggle | Target | Port |
|---|---|---|---|
| **Roblox** (RS) | RS | Roblox Studio via its built-in MCP server | ws://127.0.0.1:17613 |
| **AgentScript** (AS) | AS | A local project folder — files + terminal | ws://127.0.0.1:17615 |

Describe what you want in plain English and the AI builds instances, writes Luau/code files, sculpts terrain, tunes lighting, generates UI, runs builds and tests, and audits your project — inside Studio or directly on disk.

Website adapters require no API keys. Optional direct API providers use the provider's own billing and credentials. Chromium browsers (Chrome, Brave, Edge, Thorium). Theme is black/white outlines.

---

## Engines

- The bar above every supported chat composer carries a segmented **RS / AS** toggle. Switching engines wipes tool caches so commands cannot cross engines.
- **RS** drives Roblox Studio through StudioMCP (stdio JSON-RPC spawned by `or-agent`), including the `animation_*` workflow.
- **AS** gives the AI full control of one local folder ("the workspace") through native Rust tools — sandboxed paths, exact-match diff editing, glob/content search, and terminal execution with hard timeouts.

Large `execute_luau` scripts are auto-chunked around 24 KB so Studio's parser never hits the ~64 KB wall. Each chunk is still one NDJSON/JSON-RPC line.

## Setup

1. Open `chrome://extensions` → Developer mode → **Load unpacked** → this folder (`manifest.json`).
2. Start the bridge — **ORscript Desktop**, the Rust app in `agent/` (Windows: build once with `Build-ORscript-Desktop.cmd`; macOS: `./build-orscript-desktop.sh`; or `cd agent && cargo build --release`). Launch `bin/or-core.exe` (Windows) / `bin/or-core` (macOS):
   - Workspace window: Home / Explorer / Tools / Servers / Terminal / Settings — live Bridge / Roblox Studio / Tools / Workspace status, Studio viewport snapshots, a Luau runner that executes inside Studio, and a workspace folder you can switch without restarting.
   - Closing the window hides it to the notification area; the bridge keeps running. Background controls: **left-click the ORscript tray icon** (or launch `or-core` again) to reopen the window, right-click → **Quit** (or the **Quit** pill in the title bar / Settings) to stop the bridge and exit. If no tray icon could be created, Close quits instead of hiding so the app can never become unreachable. `--hidden` starts in the tray, `--headless` runs without any window.
   - It starts the HTTP API on `http://127.0.0.1:3000`, the WS bridges on `17613` (RS) and `17615` (AS), and the AgentScript workspace (`OR_WORKSPACE_ROOT` / `--workspace` / Settings → Workspace / `%USERPROFILE%\ORWorkspace`).
   - Runs on Windows and macOS — the platforms Roblox Studio ships for. See `agent/README.md` for build details, per-OS paths and flags.
3. **RS:** Roblox Studio → Assistant AI → ⋯ → Manage MCP Servers → Enable Studio as MCP Server.
4. Open a supported chat and click **Start agent**.

### Provider notes

- **Universal stream tap (1.65.0) — Vani Chat, ClickUp Brain, Ox Alpha and the MultiChat sites** — these adapters used to *infer* the reply from page shape (rows that look like messages, text that stopped growing for 3 s, a stop button that may or may not exist). Since 1.65.0 a MAIN-world tap (`src/providers/stream-net.js`, `document_start`) wraps `fetch`, `XMLHttpRequest`, `EventSource` and `WebSocket` on those hosts and decodes the model's reply **as it crosses the network**: OpenAI chat-completions / Responses SSE, Anthropic Messages SSE, Vercel AI SDK v4 data-stream (`0:"…"`) and v5 UI-message stream (`text-delta`), NDJSON, plain JSON and raw text (reasoning / thinking parts are skipped). The request is tied to *our* turn by a fragment of the message the extension just sent (`<html data-rs-sent>`); when a site hides the prompt behind an id, a chat-looking streaming POST inside the 20 s send window is adopted as a fallback and never overwrites a positively matched live turn. The isolated-world reader (`src/providers/stream-reader.js`, `RSStreamNet`) feeds the adapters: `readAssistant` returns the verbatim network text (commands come through exactly as written, no markdown round-trip), `isGenerating` is true while the stream is open and false the instant it closes (no stability wait), `isHardGenerating` follows the stream, and `scanError` reports HTTP 401/403 (log in), 402 (allowance), 413 (message too long - the core shortens and resends), 429 (rate limiting) and 5xx at once instead of after a 25 s silence. The DOM remains the fallback whenever the tap has nothing for the current turn, so nothing regresses when a site changes its transport.
- **ClickUp Brain (1.28.0)** — [app.clickup.com](https://app.clickup.com/) hosts ClickUp's AI *inside* the workspace app (side panel / modal from the **AI** or **Ask AI** button, or the Brain page under `/<workspace>/ai`). The same page is full of other rich-text editors (tasks, Docs, comments, Chat channels), so `src/providers/clickup.js` scores every visible editor — Brain markers (`cu-ai-*`, `ai-chat` / `brain` classes, an "Ask AI…" placeholder) score up, task/comment/doc/channel markers score down — and refuses to attach when nothing scores as Brain (the bar then says *open Brain first*). Transcript rows are read only inside the Brain surface (largest AI-marked ancestor of the composer), by role markers first and by shape second; workspace mutations outside it are ignored. Typing goes through `insertText` → synthetic plain-text paste → DOM fallback so Quill / ProseMirror state stays in sync and markdown shortcuts do not mangle JSON. Brain gets the compact system prompt + command index (`sysMaxChars` 14000, `commandListMaxChars` 12000), the catalogue is force-injected if it answers the bootstrap in prose, and its prompt extra forbids ClickUp actions (no tasks/docs/comments from our messages). Allowance / upgrade prompts surface as a bar warning. Written without a live ClickUp DOM: if Brain's markup differs, `[rs-diag] clickup.*` lines show what was found.
- **CodeCraft API (1.26.0)** — [codecraftapi.com](https://codecraftapi.com) is an OpenAI-compatible API (33 models — Claude, GPT, Gemini, DeepSeek, Kimi, Qwen, GLM, Grok, Seed… on one key) with **no web chat page**, so ORscript ships its own: popup → **CodeCraft API chat (own key)** (or the AI switcher in the bar) opens `codecraft.html`, an extension page running the exact same bundle as a hosted site. Paste a `cc_` key once (Dashboard → API Keys), pick a model from the live `/v1/models` list, press **Start**. Replies stream over SSE into the transcript (reasoning in a collapsible block, images as vision parts, `###LUA###`/JSON commands masked behind the usual chips); the key lives in `chrome.storage.local` and is sent to `codecraftapi.com` only. HTTP 401/402/429 are shown on the reply and in the bar (`modeWarning`), each conversation keeps its own `#c=…` id (**New chat** resets it), and the compact command index is used by default because every token is billed to the user's plan. **1.36.0** turned the page into a full chat app: a persistent **chat library** sidebar (every conversation saved in `chrome.storage.local` — search, pin, rename, delete, switch; reopening an agent session restores the ORscript state), **message actions** (copy, edit & resend, regenerate, delete, copy-code bars on every block), a **generation settings** drawer (temperature, max tokens, reasoning effort, custom instructions as a system message, Ctrl+Enter mode), **auto-retry** on 429/5xx, a **usage meter** (per chat + profile-wide, from the API's `usage`), reply stats (time, first token, tokens, tok/s), **export** (Markdown / JSON) and **import**, drag-and-drop images, quick prompts, a jump-to-latest pill and keyboard shortcuts. Tests: `node tests/test-codecraft.js`, `node tests/test-codecraft-pro.js`, `node tests/codecraft-e2e.js` (jsdom; `NOKEY=1`, `ERR402=1`).
- **Crax GPT** (`gpt.crax.lol`) — the site sends its own `role: system` prompt ahead of every request ("you have no tools"), which made every Crax model ignore the ORscript protocol even though the bar showed *RS Connected*. ORscript now runs a MAIN-world tap (`src/providers/crax-net.js`) that prepends the agent instructions to Crax's chat request while a session is starting or running, so all Crax models link to Studio again. Nothing is sent while the agent is off.
- **Notion AI** (`notion.so/chat`, `/ai`) — **experimental**, ported from the PlazCode Notion adapter. Notion's transcript is immutable, so command status is shown as ORscript cards next to each AI message instead of in-place chips; the bar sits on a provider-reserved strip above the composer; the Start message is phrased as plain-text *user preferences* (no Markdown blocks) so Notion's reviewer does not drop it; long tool results (the command catalogue, big script reads) are attached as `orscript_*.txt` files. Notion's own Agent is not reconfigured — ORscript only reads and writes the chat. The bar never hides on Notion: before the AI composer mounts (or on a normal Notion page) it docks to the bottom of the viewport and its status line says what it is waiting for — use the full-page chat at `notion.so/chat` or `notion.so/ai`. Hooks that exist only in the PlazCode core (native-generation respect, fresh-response gating, activity summaries) are ignored by the ORscript core.
- **ChatGPT (1.21.1)** — adapter re-synced with the current chatgpt.com DOM: the composer is found whether it is the classic `#prompt-textarea` ProseMirror box, the newer Lexical/`data-testid="composer-input"` editor or a plain `<textarea>` (Work mode), the single submit control is read through `#composer-submit-button` plus send/stop test-ids inside the composer frame, bulk `insertText` is used for the bootstrap (line-by-line only for huge results) and the composer is kept visually blank while internal messages are typed. Turn detection understands `article[data-turn]`, `data-turn-key` grouped turns and Work result units. Fixes "Start clicked but nothing is typed/sent".
- **Notion AI (1.21.1)** — composer detection no longer stalls at "waiting for the chat composer": the placeholder vocabulary was widened (Ask Notion / Ask the agent / Ask, search… / What do you want to…) and, on a confirmed `/chat` or `/ai` route, a relaxed fallback picks the chat-shaped editable nearest the bottom of the viewport after 2.5 s of strict misses (page editors never live on those routes, so this cannot touch a document). The pre-start bar line now reports how many visible text boxes the page has, which is the first thing to paste when reporting a Notion issue.
- **Provider scan (1.20.0)** — `node tests/test-provider-wiring.js` cross-checks every AI chat host against the manifest bundles, the background `PROVIDER_URLS` allow-list, the in-bar site switcher and the provider skins. It found and fixed three gaps: `agent.minimax.io`, `overchat.ai` and `huggingface.co/chat` were injected but missing from the background allow-list (the service worker refused to open/route them), Ox Alpha had no entry in the site switcher, and the switcher pointed Notion at `/ai` while the extension prefers `/chat`. Still open by design: `host_permissions` is `<all_urls>` — far broader than the 42 chat hosts actually used; narrowing it is a store-listing decision, not a code fix.

## Paint — draw it, the AI builds it

The brush button next to Settings (or **Ctrl/⌘+Shift+P**) opens **ORscript Paint**, a full-screen studio on top of the chat page (`src/core/paint.js`).

- **Tools (16):** pencil, brush (soft, pressure-aware), marker (multiply), spray, eraser, bucket fill (tolerance), colour picker, line, arrow, rectangle, ellipse, triangle, star, text, rectangle select (move/cut/copy/paste/flip), hand. Shift constrains shapes and lines; right-button paints with the secondary colour.
- **Params:** size 1–200px, opacity, hardness, flow, spray density, fill tolerance, line dash, shape mode (outline / filled / both), corner radius, star points, arrow heads, font size/bold; 24-colour palette + custom + recent colours; canvas presets (16:9, 4:3, square, portrait, 2K) or any size up to 4096², background (white/black/grey/transparent/blueprint), grid with optional snapping, mirror symmetry (X/Y/both); up to 8 layers with opacity, visibility, reorder, duplicate, merge, flip; 60-step undo/redo; zoom 10–1600% and pan (space/middle-drag).
- **Import:** paste or drop an image, open a file, or capture the Studio viewport straight onto a layer to annotate it.
- **Send to AI:** pick an intent (auto, 3D structure, top-down level, UI mockup, terrain, character, systems diagram, animation, annotate screenshot), add an optional note and scale hint, and press *Send to AI*. The painting is sent as the next user turn — ORscript starts the agent first if it is not running, waits out a busy step, attaches the PNG on sites that accept images, and always includes a **vector trace**: every element in drawing order with colour, shape, position/size in canvas %, text labels, inferred relations (arrows between elements, containment), and an ASCII occupancy map — so even image-less providers get the exact drawing. Intent-specific *HOW TO ACT* rules tell the agent to name what it sees, build it with the engine's commands, and screenshot-verify (Self-check) the result; *Plan first* asks for a short build plan before any command.
- `node tests/test-paint.js` guards the bundle wiring, the bar button/hooks, the CSS and the message builder.

## GUI Studio — design the GUI, build it in Studio

The window button next to Paint (or **Ctrl/⌘+Shift+G**) opens **ORscript GUI Studio** (`src/core/guistudio.js`), the Paint-style designer for Roblox GUIs.

- **Check + verify (1.49):** *Check* lists what would break in Studio (duplicate names, behaviours without a target, off-screen / clipped elements, text that does not fit); Build refuses on errors and, after building, compares against Studio's real viewport via `ui_layout_report`. Designs autosave and can be restored.
- **Simple mode (default):** six *Add* buttons (Button, Text, Panel, Image, Text input, Scrolling list) drop a ready-sized element with one click, twelve plain-named ready-made pieces, start cards for the templates, and a short inspector (name, text, colours, size, position, *When clicked* → open / close / show-hide a chosen element). **Advanced** (title-bar toggle) unlocks everything below.

- **Canvas:** phone / tablet / desktop / console device frames with the topbar inset preview, zoom and fit, 8 px grid, smart guides, marquee + Shift multi-select, nesting by dropping into a Frame.
- **Tools (9) + components (24) + templates (10):** draw Frames, labels, buttons, images, text boxes, scrolling frames and canvas groups; drop finished token-styled components (toggle, slider, window, dialog, tabs, dropdown, currency HUD, health bar, hotbar, shop card...); start from HUD, main menu, shop, inventory, settings, leaderboard, quest log, dialogue, loading or daily rewards.
- **Panels:** Props (every property the spec engine understands, incl. UI modifiers, layouts and per-element actions), Tree, Theme (10 token presets, live restyle), Code (editable JSON spec + generated Luau).
- **Hand-offs:** *Build in Studio* runs `ui_build_spec` through the bridge in one undoable step; *Send to AI* posts a `GUI STUDIO HAND-OFF` with the exact spec and your intent; *Import* reads a ScreenGui back from the open place; save / open `.orgui.json`.
- **Extra GUI commands (1.48.0 pack `studio_guistudio.js`):** `ui_build_spec`, `ui_export_spec`, `ui_component`, `ui_align`, `ui_distribute`, `ui_anchor_preset`, `ui_to_scale`, `ui_responsive_fix`, `ui_text_fit`, `ui_zorder_fix`, `ui_tokens_apply`, `ui_tween`, `ui_state_toggle`, `ui_find`, `ui_bulk_set`, `ui_screen_create`, `ui_layout_report`.
- **Readable themes + templates that fit + tidy builds (1.57.0):** rendering all 104 templates through the preview engine and measuring text contrast found 127 labels under 3:1 (white pills on white cards, gold-on-gold tags, dark-red horror headings). Causes fixed: the template `pill` / `chip` / `tag` helper inherited `bg_t: 1` from `txt()` so every badge was a transparent label; buttons hard-coded white text on cyan / gold / mint fills; `retro` used `PressStart2P`, which is not an `Enum.Font` (Studio silently fell back to GothamMedium). Now `text_color: "auto"` (preview, generated Luau and the Luau engine agree: white when it reads ≥ 3:1 on the fill behind, otherwise near-black; the theme's own `text` token when it already fits) is used by every template and component; light presets are softer (no pure-white surfaces), horror's primary is a usable red, neon / retro strokes are calmer, all preset fonts are real. **Check** gained three rules: text under 2.2:1 contrast (with the hex pair), anything parked under the Roblox top bar while *Ignore top inset* is on, and list / grid content overflowing its box; floating labels without a backdrop get an info + templates add a text stroke automatically. **Templates** now pick the inset for you: HUD-style screens (nothing covering the whole screen) build with `IgnoreGuiInset = false` so Roblox shifts them below its menu / chat buttons; full-screen menus keep covering the inset. **Build in Studio** no longer piles ScreenGuis up: building a second template (HUD → Shop → Settings…) offers to remove the earlier screens built this session (`instance_destroy`), Cancel keeps them. Theme tab labels each preset light / dark with its text sample. `ui_build_spec` teaches the AI the same three rules. 0 of 104 templates now have unreadable text.
- `node tests/test-gui-studio.js` (jsdom) and `python3 tests/gui-sim.py` (Luau in the Roblox simulator) guard it.

## Animation Studio — describe the motion, preview it, build it in Studio (1.52.0, uniqueness + 20 new motions in 1.53.0, Blender-style editing + spline curves in 1.54.0, compatible sets in 1.56.0, freeform choreography + the tidy three-panel layout in 1.55.0, keep-tempo combining + speed words in 1.58.0)

The running-figure button on the bar (or **Ctrl/⌘+Shift+K**) opens **ORscript Animation Studio** (`src/core/animstudio.js`), the front end of the new animation engine (`src/core/animengine.js`). The AI reaches the same engine through five commands; nothing here is hand-keyed by the model any more.

- **Engine (`ORAnimEngine`, pure JS, unit-tested):** natural-language intent (idle / walk / run / swim / climb / jump / land / crouch / sit, sword / punch / kick / thrust combos with spins and finishers, dodge, block, spell cast, transformation, emotes; style, intensity, duration, loop, R6/R15 hints) → stage plan (anticipation → action → follow-through → recovery) → keys on a 15-joint semantic skeleton with arcs, impact holds, secondary motion, weight and loop closure → validation (joint limits, discontinuities, root speed, timing gaps, loop seam, invalid numbers; 0-100 score) → exact per-bone Motor6D CFrames for the real rig (R15 / R6 / custom Motor6D rigs; R6 folds elbows, knees and waist; C0-conjugated so the numbers are right on both). Presets `fast` 24 fps / `balanced` 30 / `high` 30 + breakdowns / `cinematic` 60.
- **Commands:** `animation_generate {prompt, name?, quality?, duration?, loop?, fps?}` (one `rig_info` trip + one `build` trip - the KeyframeSequence lands in `ServerStorage.RobloxScript.AnimLib` and `rig.AnimSaves`), `animation_sequence` (combined clip + one clip per stage + blend / cancel-window guidance), `animation_refine {feedback}` ("faster attacks, more anticipation, heavier landing", exaggerate, subtle, smoother, longer, shorter, loop, variation, add a spin / landing, "2.5 seconds"; reports before → after), `animation_validate`, `animation_export_rbxmx` (a real `.rbxmx` download, works without Studio). The 24 manual `animation_*` tools, Eclipse, `animation_export` (plugin) and `animation_publish` (asks first) are unchanged.
- **Studio overlay:** prompt + quality / rig / duration / loop / fps; schematic skeleton preview (front + side, playhead, before/after ghost - **not** the Roblox renderer; the real look is one *Preview in Studio* away); timeline with draggable keys and stage bands; joint list + inspector (X/Y/Z degrees, root offset, easing per key); play / pause / stop / loop / scrub / speed; refine, variation, regenerate, auto-fix, undo / redo; validation report with click-to-seek issues; save / open `.oranim.json` (autosaved); *Build in Studio* and *Preview in Studio* run `animation_build` / `animation_preview` directly (no AI turn); *Send to AI* posts an `ANIMATION STUDIO HAND-OFF`.
- **Every clip is its own (1.53.0):** each prompt seeds a *persona* (leading side, weight side, head tilt, shoulder drop, arm rest - loose / hips / behind / folded -, breath depth, sway phase, fidget - look / hands / shoulders / weight -, bounce, arm asymmetry, head bob, hip sway, stride lean, tempo, easing flavour soft / snappy / bouncy / mechanical) that reaches the stance, idles, cycles, emotes and stage timing; combos are *choreographed* from a wider strike pool (rising / diagonal / backhand cuts, elbow, haymaker, knee, front kick) with no back-to-back repeats and explicit words kept in prompt order ("overhead then thrust"); every clip carries a `fingerprint` and `generate({avoid})`, `animation_generate {variations:N}` and the **New take** button re-seed until it differs from everything already produced. **Mirror** (button, `{mirror:true}`, "left-handed" / "mirror" in the prompt or feedback) swaps left/right exactly and round-trips. New motions: sneak, strafe left/right, walk backwards, crawl, push-ups, tread water, fly, sleep, kneel, aim idle; hit reactions (front / back / left / right), knockback, death (backwards / forward, ends lying flat), dash, slide, back / front flip, throw, shoot (pistol / rifle, N shots, burst), archery (draw → release), pick-up; emotes salute, facepalm, shrug, taunt, nod, head-shake plus sub-variants of wave (both hands / shy), cheer (fist pumps), dance (groove / bounce-point), point (sky / side), clap (slow overhead), bow (theatrical). "with root motion" lets the root travel inside walk / run / dash / slide clips (declared as a limitation; the loop seam keeps the offset).
- **Blender-style editing (1.54.0):** orbitable 3D viewport (drag = orbit, wheel = zoom, Shift-drag = pan, double-click = reset; 3D / Front / Side / Top / Back chips, hotkeys 5 1 3 7), onion skin (O), auto-key (K), click a joint handle to select it, drag the hand / foot effectors to pose with analytic two-bone **IK** (multi-pole, ~97-99 % of in-limit targets reached), the key workbench (1.64.0 - replaced the dope sheet and graph editor, see below), pose tools (Shift+D duplicate, X delete, Ctrl+C / Ctrl+V copy-paste, Ctrl+Shift+V X-flipped paste, pose library saved in the browser), clip tools **Smooth / Eased|Spline / Plant feet / Simplify / Reverse / Bake / Cycle offset**, upper-body **layering** (walk + wave, run + aim; stretch or loop fit, weight 0-1), a smoothness read-out (mean angular acceleration, 100 = silky) and a 60-step undo. **Spline curves:** Roblox easing is per segment, so the velocity resets at every key; `clip.interp = "spline"` (High / Cinematic presets, *Smooth*, "smoother" feedback, the Eased|Spline button) interpolates with auto-clamped C1 Hermite curves instead (loops wrap the seam tangents, holds stay flat, impacts keep their eased snap). Measured smoothness on the same clips: walk 63 → 92, sword combo 33 → 77, wave 72 → 97. Studio and `.rbxmx` receive spline clips baked to the frame grid plus every authored key (Linear, markers kept - a 4 s cinematic combo is ~240 keyframes); long bakes are written in several `build` trips (`more` / `append`), so the Animation Editor shows the dense bake - keep Fast / Balanced (eased, sparse keys) when you want to hand-edit in Studio.
- **Any prompt (1.55.0):** the old engine folded unknown phrases into the same idle - now a freeform layer sits in front of the classics. An **act lexicon** (70+ everyday / work / sport / social / reaction motions: drink, eat, phone, type, dig, chop, push, pull, row, bike, drive, fish, sweep, paint, guitar, open a door, knock, lift, carry, hug, handshake, high five, salute, curtsy, dab, floss, twirl, squat, push-ups, jumping jacks, golf / bat swing, basketball shot, kick a ball, superhero landing, cower, surrender, dizzy, sneeze, shiver, cry, stomp, stretch, meditate, pant, think, look around…), **`A then B then C` chains** (separate clips blended into one, stage per part), **`X while walking / running / sneaking`** (legs + root from the cycle, upper body from the act), a **pose grammar** (`raise the left arm`, `shake your head`, `lean back and look up`, `kick the right leg`…), **moods** on top of any motion (tired, old, drunk, sad, happy, angry, scared, proud, injured, cold, energetic - `tired old man walk`), **counts** (`knock 3 times`, `do 5 squats`), and - only when nothing is recognised - a **seeded improvisation** that is labelled as such in the clip's limitations (never silently the same idle). Feedback understands the same vocabulary (`make it drunk`, `no mood`, `then wave`, `start with a salute`). Two different prompts never share a fingerprint; the 50-prompt sweep in `tests/test-anim-freeform.js` proves it. Limits: the pose grammar is heuristic (verb + side + part + direction), fingers / faces are not animated, acts are authored silhouettes - not motion capture.
- **Tidy layout (1.55.0):** left = three numbered cards (1 Describe → Generate / Regenerate / New take / Mirror, 2 Refine with feedback, 3 Edit & deliver cheat-sheet) with the example chips folded away; centre = a quiet viewport (onion / auto-key / before-after top-left, view chips top-right), transport, timeline, the collapsible key workbench (1.64.0) and a single delivery row (Send to AI · Export .rbxmx · Preview in Studio · Build in Studio); right = **Pose | Clip | Check** tabs (joints + selected key + pose tools + pose library / curves & cleanup tools with one-line hints + Layer (NLA) + Stages / validation report with the score badge on the tab). Improvised clips open the Check tab so the explanation is seen.
- **Key workbench (1.64.0):** the strip under the timeline is now a professional key toolkit instead of a dope sheet / graph editor: a **key strip** (one chip per key - time, role glyph `!` impact `=` hold `~` breakdown, ease, marker flag; click to select), **Breakdown** (tween machine: insert a key at the playhead favouring the previous or next pose 0-100 %, `B`), **Hold** (moving hold N frames after the selected key, later keys slide back, `H`), **Nudge** (one frame either way, `,` `.`), **Marker** (KeyframeMarkers on the key - `footstep`, `hit=right`, `sfx=swing` - exported to `.rbxmx` and built in Studio so `AnimationTrack:GetMarkerReachedSignal(name)` fires), **Ease all** presets (Snappy / Organic / Mechanical / Bouncy / Elastic / Anticipate - impacts get the preset's arrival, holds stay flat), **Overlap** (follow-through: elbows, wrists, head, knees, ankles trail by N frames, loops stay closed), **Retime** to an exact length, **Arcs** (motion trails of hands / feet / head in the viewport, `G`) and a **timing read** (counts of impacts / holds / breakdowns / markers / overlap plus notes on even spacing, twinning and missing anticipation). The Refine box understands the same tools by name ("more follow-through by 3 frames", "hold the impact 4 frames", "bouncy").
- **Sets of compatible clips (1.56.0):** "idle, walk, run, jump and attack animations for my knight" is a *set*, not one clip - the engine splits the list (`splitSet`; "walk then wave", "jump and land", "punch and kick" and "slow walk, fast walk" stay single clips), generates one clip per item with **one shared character seed** (same lead side, arm rest, tempo, easing), prefixes the names (`KnightIdleLoop`, `KnightWalkLoop`, …, no doubled prefix), assigns `Idle / Movement / Action` priorities and scores the set (`compatibility`: same rig / fps / persona, stance distance + root height between the idle and every other clip, the `AnimationTrack:Play(fade)` to use, locomotion that forgot to loop). Chat: `animation_generate` auto-splits such prompts, plus explicit `animation_set {prompts[]}` and `animation_compatibility`; later single clips keep the session character (`new_character: true` resets). Studio: new **Clips** tab (every session clip with built / same-char badges, click to switch, × to drop, **Build all** = one KeyframeSequence each, **Export all**, **Check set**), a *Same character as my other clips* box, and a *Set compatibility* section under Check. Two silent bugs fixed on the way: exported / built easing directions were inverted (Roblox `Pose.EasingDirection` is backwards from TweenService - `In` there means ease-out) so every eased clip decelerated where it should accelerate; and the schematic root height was 0.5 studs too tall, so *Plant feet* and every grounded clip sank the rig half a stud into the floor. The Luau preview now samples in real time through the same eased sampler Roblox uses, and the test simulator slerps + eases like the engine.
- **Honesty rules:** Studio offline → the clip is generated + validated and clearly marked NOT built; a refused build is an error with Studio's reason; asset ids only ever come from a publish result.
- **The tempo stays yours when clips are combined (1.58.0):** three things made combined animations feel rushed. (3) A duration the model picked (`animation_generate {duration}`) squeezed whole sequences - it is now soft: it may lengthen a clip but never trims below 75% of the natural length, and the clip says so; `"in 2 seconds"` in the prompt or the Studio duration box still pins it exactly. ### Theme preview (no extension load needed)

`tools/theme-preview/` renders the real `overlay.css` with the real bar / settings / approve DOM ids so the skin engine (backgrounds, corner decorations, button states; Night is the only skin exposed since 1.39.1) can be checked in a plain browser:

`node tests/test-theme-visuals.js` guards the 1.19.7 visual layer (per-theme tokens, swatch photos, SVG corner ornaments + inside textures, pill button states) and the sound packs, and since 1.39.1 also asserts the theme picker is gone. Decorations are designed SVG motifs (`--orx-orn` in `overlay.css`) painted with the theme gradient — never emoji or text.

### Sound packs

Every theme ships seven hand-tuned Web Audio effects — `start`, `done`, `stop`, `error`, `ok`, `click` and a `special` signature — defined as data in `THEME_SOUNDS` (`src/core/main.js`) and rendered by a single synth (`playSfx(kind, themeId)`): oscillators with glide, lowpass, detune/chorus and vibrato, plus filtered noise. Every effect is under one second and never loops. The ♪ pills under the theme picker preview the current pack; the preview harness above plays the same code.

## Privacy

There is no OrScript telemetry. Local tool bridges use `127.0.0.1`; enabled API integrations contact only their configured HTTPS provider endpoint. AgentScript stays inside the workspace root unless you flip FULL ACCESS.


## Studio MCP reliability

Studio operations use Roblox Studio's supported MCP server through the local OrScript agent. Timed-out MCP calls are not replayed, `script_read` has a bounded 30-second extension timeout, and reconnect retries are limited to disconnected read-only requests.

## Creation-engine capability profile (2.21.0)

`TotalCreation.profileFor(profile, TotalOrchestrator.capabilities(P))` caps the user's creation quality profile by the adapter's REAL flags: a tight prompt (`sysMaxChars` < 16000 or `compactCommandList`) shortens the spec brief (≤ 420 chars) and the static-review notes (≤ 3 per run, ≤ 320 chars each); a `sendCharBudget` below 1200 raises the brief threshold to 3 deliverables. Nothing here is a model capability - these are prompt-transport limits read from `src/providers/*.js`.

## Shared pipeline every provider feeds

`typeAndSend` → site → `readAssistant` (stream tap first where present, DOM otherwise) → `src/core/parser.js` (JSON · `###MCP_TOOL###` · `###LUA###` / `###LUA:Server|Client###` · `###CMD name###` envelopes · native `<tool_call>` / DSML) → `TotalCommandContract.prepare` (aliases, enums, ranges, required params) → `command_registry` / skills → `background.js call_tool` (Roblox bridge 17613 / local 17615, Blender ops) → result (compressed · mode auto-check · **2.21.0 creation tracker**: coverage / integration evidence + static Luau review of the source the model sent) typed back by `typeAndSend`. Before a final answer is accepted the shared gates run in order: creation coverage gate (2.21.0, deliverables of the request vs the command log, bounded by the creation profile and the adapter) → work-mode evidence gate → reasoning-effort gate; the run ends with a creation report (Activity). Providers never parse commands themselves; `findToolBlockSpot` only masks command blocks visually.

## Send-path contract (1.85.0 / 1.86.0)

Commit ONCE (send button click; else the composer's own form submit / Enter), wait a bounded 2.5 s for a landing proof (our text left the composer · stop control up · new user row · stream tap saw the request), ONE alternate mechanism only while our text is verifiably still typed, then an honest `*.send.landed` / `*.send.unconfirmed` (or `*.tas.sent {sent, how, proof}`) diagnostic without the text. An adapter may opt in with `typeAndSendFalseMeansNoSubmit: true` only if `false` guarantees it issued no submit action; the core surfaces `scanError` and allows at most one bounded retry after the provider is idle. `typeAndSendSingleCommit: true` instead prevents a second core submit after any commit; if landing proof stays ambiguous, the core warns and aborts rather than blindly re-clicking. Legacy return values remain opaque and are not generalized. Adapters marked *single click / Enter* already committed once (ChatGPT, Gemini, Kimi, Qwen, GLM, DeepSeek, Claude); the loop-based ones were repaired in 1.85.0 (Vani, MiMo, ClickUp) and 1.87.0 (Arena, Meta, Ox Alpha, MultiChat × 11 ids). Claude and DeepSeek keep a bounded re-click loop ONLY on the screenshot path (send button disabled until the upload finishes; the site clears the composer synchronously on accept) - inconsistent with the rule, not observed to duplicate, left as is and listed here.

## Known limitations (honest)

- `multichat.js` is the shared adapter for HuggingChat, OpenRouter Chat, AI Free Forever (including the `www` redirect) and Langdock. It uses site-profiled composer hints with semantic fallbacks, composer-scoped send discovery, single-commit/no-submit contracts, DOM transcript fallback and the universal tap for recognized stream formats. Synthetic DOM/jsdom cases cover delayed clearing, disabled controls, login routes and scoped send selection (`tests/test-multichat.js`, `tests/test-provider-parity.js`); they are not snapshots of the live sites. OpenRouter composer discovery on dashboards with several inputs remains **unverified**; AI Free Forever and Langdock composer, transcript, stream format, login gates and account requirements remain **live-unverified**; image attachment is disabled pending upload-UI verification. TotalScript does not bypass provider authentication.
- Qwen's Monaco code-snapshot MutationObserver is document-wide (singleton, traced, never duplicated) - a known performance suspect on very long chats, unchanged.
- Live Studio / Blender / site behaviour is outside what this repository's tests can prove.
